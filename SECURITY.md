# Política de segurança

## Versões suportadas

Enquanto a v0.1.0 estiver em avaliação, somente a versão mais recente do ramo principal receberá correções de segurança.

## Relatando uma vulnerabilidade

Não abra uma issue pública com detalhes exploráveis, caminhos locais, tokens ou dados pessoais.

**Ação obrigatória antes da publicação:** habilite o *private vulnerability reporting* do GitHub ou informe aqui um endereço de segurança real e monitorado. Nenhum contato fictício foi criado. Até essa configuração existir, o repositório não oferece um canal adequado para relatos sigilosos.

No relato, inclua versão, plataforma, passos mínimos de reprodução, impacto e qualquer mitigação conhecida. O mantenedor deve confirmar o recebimento, avaliar severidade, coordenar correção e só então publicar detalhes.

## Escopo

Falhas de memória, travamentos causados por entrada não confiável, escape de caminhos de projeto, resolução indevida de módulos e exposição de dados são exemplos relevantes. Erros puramente pedagógicos ou sugestões de recursos devem usar issues comuns.
